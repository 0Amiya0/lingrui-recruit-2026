# LLM 完善设计

## 目标与范围

在现有 nanoGPT、字符级 Shakespeare 数据、1200 步日志与 checkpoint 上，补齐 task.md 的三个任务：Transformer 理论、源码对应、真实训练及文本生成证据。保持学习任务定位，文档区分源码事实、实验观察与解释性推测。

## 路线选择

推荐：保留已有模型和日志，完善外层脚本、文档与验证，再以独立目录做短训练验证。工作量集中在现有缺口，能够利用真实历史产物。

替代一：仅修笔记，投入较少，但复现、采样与错误处理问题仍存在。

替代二：从零重训完整 1200 步，可生成全新证据，但 CPU 耗时较长；先验证现有 checkpoint，再判断是否需要重训。

## 文件与职责

- `notes/01_Transformer笔记.md`：以原论文第 3 节为准，明确 Post-LN 架构、自注意力/交叉注意力、缩放、多头、位置编码与残差。
- `notes/02_nanoGPT笔记.md`：当前源码文件职责、Pre-LN、权重共享、训练每位置 next-token 目标、训练与推理输出形状及采样。
- `notes/03_实验报告.md`：历史训练证据、当前验证证据、参数量、环境、耗时依据与输出局限。
- `generate_demo.py`：命令行指定 checkpoint、meta、prompt、seed、采样数、长度、温度、top-k、设备和输出路径；从 checkpoint 配置构建同结构随机模型；分别控制初始化与采样随机数。
- `plot_loss.py`：可导入日志解析函数与命令行入口；区分训练步日志与 eval 日志，导出 CSV 与图片，空日志明确报错。
- `scripts/verify_environment.py`：采集环境、源码 revision、数据尺寸与 checkpoint 摘要，输出 JSON。
- `requirements.txt`、`README.md`：实际依赖、工作目录、准备/训练/恢复/生成/测试命令，CPU 配置与输出说明。
- `tests/`：面向重要行为的测试，包括因果性、输入输出形状、next-token 数据偏移、生成参数校验、种子复现和日志解析。
- `artifacts/verification/`：当前检查的环境 JSON、CSV、生成对照和短训练日志，与原始实验文件区分。

## 数据流与错误处理

文本通过字符词表编码为 uint16 token ids；训练窗口输入为 ids[i:i+T]，目标为 ids[i+1:i+T+1]。模型每个位置预测紧随该位置的 token，而不是只训练最后一个位置。生成从 checkpoint 恢复模型，按最后位置 logits 采样，超过上下文长度时裁剪输入。

缺失 checkpoint/meta、空 prompt、词表外字符、非正温度、非法采样参数、配置与权重不匹配应明确报错。脚本导入不得触发模型加载或生成。原训练产物保留，短训练另设输出目录。

## 验证与验收

1. 逐项核对任务要求与三份笔记，引用原论文和本地源码；纠正 ln(V) 是均匀预测的交叉熵而非下界。
2. CPU 跑行为测试，证明未来 token 不影响此前位置的输出、形状正确、生成可复现。
3. 实际加载现有 checkpoint，核对迭代数、配置与日志记录；真实生成训练/随机模型对照。
4. 在独立输出目录跑小规模训练验证训练入口，再加载新 checkpoint 生成。
5. 报告所有实测结果；无法由现有日志恢复的完整训练墙钟耗时只能标注估算。

当前已确认 Python 3.13.5、PyTorch 2.14.0+cpu、NumPy 2.1.3、CUDA 不可用。根目录不属于 Git 仓库，nanoGPT 为嵌套仓库，其 CPU 配置是已有未跟踪文件；不擅自将整个工作区初始化为仓库或提交现有文件。

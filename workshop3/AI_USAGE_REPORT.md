# AI 使用报告

> Workshop 题目三：标签噪声下的小样本图像分类（Few-shot Image Classification under Label Noise）

- **项目目录**：`Lingrui/workshop3/`
- **完成时间**：2026-09

---

在列出使用报告前，想稍微谈谈笔者对Agentic Research的看法：

AI 和 agent 正在把科研中大量"执行层"工作——写训练脚本、调参、跑实验、整理文献、画图、润色论文——变得低成本、可并行、可自动化。可以在几个月内完成过去需要一两年才能积累的工程熟练度。但**AI 加速的是做，不是判断**。李沐近期说过：Agent是让能力*10，不是让其+10。
问题定义、实验设计、因果解释、失败诊断、结论取舍，仍然必须由人深度参与并确保完成，而且这些能力**只能通过亲手做点事情来培养**。这里存在一个悖论：AI 帮你跳过了大量执行环节，但恰恰是这些环节在训练你的判断力。如果全都外包给LLM，你会变成一个只会按按钮、无法独立判断 AI 输出对错的AI奴。当执行被外包，判断力没有地方锻炼；当判断力缺失，AI 输出难以验证；当验证链断裂，不可复现性积累；科研生态的混乱性和长期成本（比如复现所花的时间和算力成本，正确率，或者从一堆水论文中复现到真正有价值的paper）上升。这是一个正反馈。所以，终归得保留自己的科研品味和验证的手感。


---

**复现是训练判断力最有效的方式**——遇到论文没写的细节问题、AI无法轻易或鲁棒地解决的bug、需要自己判断的取舍问题到底。
在学习阶段，每段 AI 生成的代码，自己先读一遍，保证能解释每一行在干什么。
尽量穿插手撕环节，不然如果需要实现AI未曾训练过的新逻辑，AI不一定能给出所需要的最高效的代码。所以模型架构部分，以及核心实验部分（尤其是idea和method），需要有一定熟练度。还有就是，目前所谓的ML科研**大多更像工程问题**，例如已知的优化方法，最优性证明一直成问题，这就导致，调参的过程可能需要**人的经验和感觉**。
所以，感觉一个好的习惯是，做好prompt工程，保留好context，借此从LLM上蒸馏到知识，定期反思：这个任务不用 AI 我能做吗？

#### 几个不要：
- 不要用 AI 生成引用而不验证。
- 不要用 AI 跑实验而不理解代码。
- 不要用 AI 写论文而不自己检查逻辑。
- 不要因为 AI 能生成就大量产出低质量实验。
- 不要把"会用 AI"当成"会做科研"。

## 2. 使用范围：

| 环节 | AI 的贡献 | 人做了什么 |
|---|---|---|
| **选题与问题定义** | 帮助梳理 `task.md` 的硬性要求（对称噪声、筛选/重加权/鲁棒损失类方法） | 确定题目、阅读、学习并理解任务要求 |
| **代码实现**（`src/`、`scripts/`） | 生成/修改 backbone、baseline、method、metrics、config、dataset 等模块及全部实验脚本 | 审阅代码、提出修改意见、确认需求变更（CPU → GPU 支持）、调超参 |
| **实验编排**（`run_all.ps1`、`run_experiments.py`） | 编写 Windows PowerShell 全流程脚本与跨平台 Python 编排器 | 跑实验，产出 `results/` 全部数据与图表，阅读并分析产出 |
| **结果回填与论文**（`paper/short_paper.md`、`.tex`） | 起草英文 short paper 与 ICLR 2023 LaTeX 版；根据 `results/` 回填表格数值、嵌入图片、更新结论 | 逐项核对内容，修改、决定论文定位与表述 |
| **文档**（README、本报告） | 撰写/改写 README 与 Plan  | 提供使用场景（GPU 机器、显存、跨平台）等需求 |

## 3. 人机分工总结

- **AI 负责**：代码骨架与实现、实验脚本、论文初稿、图表代码、README 与报告等「生成型」工作。
- **人工负责**：
  1. 研究问题与方法的idea提出与决策；
  2. 实验的实际运行；
  3. 结果的核对、论文结论的修改润色，以及最终把关；
  4. 本报告所述内容的确认与签署。

## 4. 验证与质量保障

AI 生成内容经过以下验证，而非直接采用：

1. **代码语法检查**：对全部 `.py` 文件执行 `python -m py_compile`，通过。
2. **导入冒烟测试**：对全部实验脚本执行 import 自检，无导入错误。
3. **指标单元测试**：`scripts/test_metrics.py` 对 AUROC、risk-coverage（AURC）做 sanity check，通过。
4. **PowerShell 脚本校验**：对 `run_all.ps1` 做 AST 解析检查（并修复了 UTF-8 BOM 导致的 Windows PowerShell 5.1 解析问题），通过。
5. **论文数字核对**：论文中的表格数值逐项对照 `results/summary_meanstd.csv`、`results/ablation_summary.csv`、`results/error_analysis.json` 回填，并与原始逐种子 CSV 交叉验证。
